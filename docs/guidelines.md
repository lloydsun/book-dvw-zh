这份文件是 `content/book/**` 里所有译文的成文约定，管**语气、语域、写法与专名**。改动译文之前请通读一遍：目标是与全书一致，而不是与个人偏好一致。

## 语域与语气

- 描述式陈述，不是命令式；作者以当事人身份讲亲历与判断。第一人称「我」照译，**不改成「笔者」「本书」**。
- 断言强度照搬源文：`may` = 可能／可以，`should` = 应当，`must` = 必须。不加强、不削弱、不改成模棱两可的话。
- 作者的自嘲、冷幽默与括号旁白（`(that's me)`、`That's enough blowing my own trumpet`）**照译并保持玩笑语气**，不顺平、不删、不改写成正经说明。
- 作者对史实与同行人物的评价（`talented`、`anarchic`、`bloody`）按原强度落笔，不美化也不加重。
- 反讽与不确定语气（`perhaps`、`somewhat`、`as it were`）照译；不得为了通顺把保留意见改成断言。
- 作者偶尔写错、或原文本身前后不一致的地方（人名拼写、机型名 `DecSystem-10` 与 `DEC-10` 并存），**照抄**，不要"顺手改对"；确实疑为原文笔误的，在 PR 说明里提出来。

## 专名

- **人名、地名、机构名**：首次出现作「中文（原名）」，其后只用中文。音译按新华社《世界人名翻译大辞典》的规范；韩文、日文等汉字文化圈姓名按本人汉名（如 Jake Song 本名 송재경，作「宋在庆」，不按字面作「杰克·宋」）。
- **游戏名**：用书名号，首次出现作 `` 《译名》（原名） ``，其后只用 `` 《译名》 ``。
  - 括注在书名号**之外**，不写作 `《译名（原名）》`——书名号标记一个完整标题，括注是对标题的说明，层级低于标题。
  - 原名不再自带书名号（不写 `《EverQuest》`）：书名号标记的是中文标题。标题自带括号时写作 `《译名》（原名：Original Title）`。
  - 缩写（EQ、UO、M59、AC、TSO、SWG、DAoC、AOL、SOE）保留原形，随首现的中文括注一并给出。
- **不译的名**：无通行中文译名的代码库名、程序名、语言名与标识符（MUD1、MUD2、AberMUD、TinyMUD、LPMUD、DikuMUD、LambdaMOO、MUSH、MUCK、MOO、LPC、MUF、BCPL、object32……）保留原形——它们不是作品名，是程序与家族名，硬译会让读者在中文技术文献里找不到对应物。**是否加书名号以术语表的逐条裁定为准**（MUD1／MUD2／TinyMUD／LPMUD／DikuMUD 等加 `《》`；MOO／MUSH／MUCK 等因与常用词撞车而不加）。
- 中文圈只有原形、没有通行译名的机构名（CompuServe、GEnie、Turbine、NCSoft、Skotos、Verant 等）**保留原形**，由术语表逐条钉死，不在正文里临时音译。
- 表里没有的词**不要自造中文**：正文保留源文的英文原形，首次出现时在英文之后加一个括注给出中文候选，形如 `MUDDL（Multi-User Dungeon Definition Language，多用户地牢定义语言）`。源文自己已经给出的英文括注（`BBS (bulletin board system)`、`JANet (Joint Academic Network)`）保留英文括注，把中文候选并进同一对括号，不另起括号。
- 中文技术文献里已有固定译名的通用技术词（大型机、汇编语言、引擎、解释器、分组交换、拨号、调制解调器、公告板系统、范式、可维护性……）直书中文，不算「自造」；只在会与同段其他词混淆时才补英文。
- 已在译文里定型的写法沿用，不重新发明：`virtual world` = 虚拟世界，`player` = 玩家，`character` = 角色，`MUD`、`MU*`、`MMORPG` 保留英文原形。

## 标点与句法

- 标点用中文全角（，。；：？！），引号用弯引号 “ ” ‘ ’，破折号用 ——；英文括注内部保持英文标点。
- 句长随源文：允许长句，但不把英语的从句链原样搬成读不通的中文——按作者本意重排语序、补出必要的连接词。
- **不出现括号套括号。** 括注里还要再加说明时，不嵌套：
  - **首选**把外层旁白搬到主句末尾，作全句的追补括注；句末括注是句子的一部分，标点写在右括号之外，作 `……源自它（克莱夫·林杜斯那个构思巧妙的《Void》[^9] 比它早几个月）。`
  - 搬不动时（旁白与主句咬合、或句末已有括注／脚注）才退用破折号夹注（`——……——`，末尾不再补标点），或拆掉外层括号重写句子；不要把夹注插在主谓之间。
  - 源文自带括号的引文、书目与插入语（`MUDs (Multi-User Domains)`）照源文保留，不算嵌套——那是内容，不是排版选择。
- **夹注不插进语法咬合处**：夹注（破折号或括号）不落在主谓之间、修饰语与「的／地」之间、「在……里／中」这类介词结构与方位词之间，夹注之后也不再赘一个逗号／句号。
- 年份、数字、位宽用阿拉伯数字（1978、36 位、1 位）；年份区间沿用源文的短横线形式（1984–85、1978–1985）。
- 代码、标识符、汇编语言名、机型名、文件名、路径、程序名保持大写与连字符原样（MACRO-10、DecSystem-10、DUNGEN、ADVENT、BCL、PSS）。

## 结构：哪些能动、哪些不能动

- **front matter 只动 `title`。** `weight`、`type`、`book_kind`、`menus`、`cascade`、`outputs` 等键与取值**逐字节保持不动**（`book_kind` 只在书根出现）。
- **正文里不写标题。** 页面标题一律取自 front matter 的 `title`，层次由目录层级表达（一节一个文件）。只有 `_index` 页（书根、章首页）保留源文 `##` 那一级的附加小节（目录、致谢、作者简介），照译、不增删。
- **段落数与源文一致**：源文因跨页被切成两段的句子并回一段，不合并不同段落，也不新起段落。
- **文件路径不要改。** `01-02-Some-Definitions.md` 这样的路径是与原文仓库对应的坐标，改名会在下次同步时被覆盖回去，也会让别处的引用断掉。
- **脚注** `[^n]` 同位同号：编号照源文（源文从 `[^2]` 起就写 `[^2]`），不重排、不增删、不从 1 重新起算。标记前保留一个半角空格，定义照源文顺序放在文末，`[^n]:` 后接译文。
- **链接与图片目标字符串逐字节保持**（本类页面通常没有外部链接）。

## 图片与表格

图片放在仓库的 `assets/figures/` 下，正文用站点绝对路径引用（`/figures/Figure-2_1.png`）。**要进「插图目录」的图片必须登记编号**，写法是属性行紧跟在图片下一行：

```
![图 2.1](/figures/Figure-2_1.png)
{#fig-2.1 num="2.1" caption="总体架构"}
```

- `#id` 取 `fig-<num>`；`num` 用与正文一致的「章.序」点号形（`2.1`，不是 `2-1`）；`caption` 是**不带**「图 N.M」前缀的纯题注。
- 正文里**不另写**「图 N.M 题注。」这句话——它已由 `caption` 渲染，重复写会显示两遍。图内自带图例时图例照常留在正文，只去掉题注那半句。

表格用普通 Markdown 表格，登记写法与插图同形（仅中文侧已登记 6 张）：

```
| 代码库 | 驱动程序 | … |
|---|---|---|
| DikuMUD | 代码 | … |
{#tbl-1.1 num="1.1" caption="代码库差异"}
```

属性行**紧跟表格最后一行**（中间隔一个空行）。例外是表 1.3：源文那张表是裸 HTML `<table>`（两级表头＋`colspan`／`rowspan`），属性行对它无效，用的是 `{{< tbl num="1.3" caption="…" >}}…{{< /tbl >}}` 把整张表包起来。

**改动编号图片或表格时，编号、`id`、正文里的交叉指称要一起改**，别留下半个。当前状态：8 张编号插图（图 2.1–3.6）与 6 张编号表（表 1.1–5.1）已登记；`assets/figures/` 里另有 3 张作者照片无编号、不登记。

## 勘误标记

源文确有笔误、而译文按本意处理时，用**内联 HTML 标签**包住整块（当前 7 处，在 `01-05`、`01-07`、`01-08`、`04-36`）：

```
<em>{勘误：……}</em>
```

标签紧贴花括号外面、**不加空格**，括号里紧跟全角冒号，括号内一字不动：全角冒号与原有间距一律照旧，从而不引入任何新的空白，也不必再为它补空格。

**不要用 Markdown 星号**：星号紧跟在汉字之后、后面又是 `{` 时会被 CommonMark 的「左右侧翼」规则吃掉——既不能开也不能闭，会原样渲染成字面量 `*{勘误：……}*`（`04-36` 曾经就是这么翻车的；补空格能绕开，但会动源文排版）。内联 HTML 标签不进强调配对逻辑，前后是什么字符都稳。

非勘误的强调维持 Markdown 星号写法：表题与强调词用加粗 `**…**`，书根的英文书名用斜体 `*Designing Virtual Worlds*`。它们都是纯中文或纯西文短语，星号后紧跟空格或汉字，不受上面那套限制。

## 目标读者

- 读者是中文的虚拟世界／游戏设计者、研究者与爱好者，**读整本书**而不是查文档。
- 读者知道「虚拟世界」「玩家」「角色」这些概念，但**不知道** 1978–1985 年间英国的具体院校、机型、程序与人物；这类专名首次出现时要有托底信息。
- 缩写首次出现要能就地知道它指什么（MUD、MUDDL、BCPL、EPSS、PSS、JANet、BBS、ARPA）；源文没有解释的缩写按源文处理，不含糊补英文全称。
- 读者读的是**译作**，不是英文原文的对照；句子读起来要像中文写作，专名与非通用术语才保留英文。

## 提交

```sh

```

`error` 必须清零；`advise` 逐条判断后在 PR 说明里交代你怎么处理的。机械检查通过不等于改得好——判断类的问题机器查不出来，这正是这个仓库需要人的地方。
