你启动浏览器的时候，它指向的是哪个页面？说来也许让人意外，大多数人的答案是“我的 ISP 在安装软件时把它设成的那个页面”。他们每天早上看到的万维网第一屏，就是 ISP 给他们看的东西。

虚拟世界有很多办法让玩家按自己的偏好定制体验。比如在文字世界里，有些人希望任何时候都看到完整的房间描述，有些人则希望任何时候都看简短的描述。有一些命令可以让玩家自己选择采用哪一种。然而，这两种选择里总有一种是默认设置，而新手用的就是这一种。在《MUD1》里，你第一次进入一个房间时会看到完整描述，之后再进去看到的就是简版。这样新手就不至于迷路。到后来，他们会在绘制精确地图时一律使用完整描述，在其他所有时候一律使用简短描述。不过，“后来”是后来的事。刚上手时，他们得到的是默认设置，而默认设置说的是：“去探索吧！”

默认设置决定了虚拟世界的基调，因为所有新手都是在默认设置下玩的。随着经验增长，他们不可避免地会去定制其中一些设置。不过大多数选项仍会保持默认。因此，设计者对默认设置的选择，会长期影响人们对一个虚拟世界的观感。默认设置比看上去更重要。

为了说明这一点，我们来看看模式，因为在某种意义上，正是模式确立了一个世界“讲的是什么”。

所有虚拟世界都假定有一个用于自由形式输入的硬件设备；通常就是键盘。玩家敲进一些文字，按下回车，然后——然后呢？这取决于当前的模式。在文字世界里，这一行通常被解释为一条命令。

```
open door
north
get book
```

这就是命令模式。

在图形化世界里，这一行通常会被当作对话来处理。

```
Follow me!
What happened? You were supposed to be
following!
Hey! That’s mine!
```

这就是对话模式。聊天室通常也默认采用对话模式。

那么，这里隐藏的深度在哪里？你又不是不能在对话模式下行动，也不是不能在命令模式下说话。

当新手进入一个默认是命令模式的世界时，这个世界传达给他的信息是：这是一个可以做事的地方——它强调的是对世界采取行动的自由。如果默认是对话模式，信息就是：这是一个可以交流的地方——它强调的是与其他玩家互动的自由。因此，你也许会以为，文字世界的玩家做得更多，图形化世界的玩家说得更多。

实际上，在图形化虚拟世界里，默认做法是大部分时间都使用鼠标——而鼠标算不上自由形式的输入设备——这就使“有限的做事”与“无限的说话”之间拉开更大的分野。如果你想说话，或者想尝试任何复杂一点的事，就得先停下正在进行的操作。作为管控人群的建议，这很合理。但对身处这支被管控人群中的个体来说，多少有些令人不满。

设计者设定默认模式。默认模式塑造玩法风格。因此，设计者可以通过改变默认模式来鼓励或抑制某种玩法风格。于是，一个简单的、几乎随手做出的设计决定，就能对一个虚拟世界的精神气质产生长期影响。

请注意，主要的选择固然是在命令模式与对话模式之间，但虚拟世界里还会用到其他模式。已经演化出的一条惯例是：用一行中的第一个字符来切换模式，此切换对该行剩余部分生效。通常还会有一个选项，让某种模式保持开启或关闭，直到另行通知为止，不过目前还没有出现这方面的标准语法。

表 2.1 列出了最常用的几种模式，以及用来开启它们的首字符（这些首字符有时互相冲突）。

| 模式 | `Leading Characters` | 说明 |
|---|---|---|
| Command | `> /.` | 输入会被当作发往服务器的一条直接命令。 |
| Conversation | `` ‘“` `` | 输入会被当作 say 命令的一个参数。 |
| Coding | `@` | 输入会被当作一条脚本语言命令。 |
| Acting | `;:` | 输入会被当作 pose/act/emote 命令的一个参数。 |
| Help | `?` | 输入会被当作 help 命令的一个参数。 |
| Switch | `/ \ $` | 输入发给客户端或前端，而不是服务器。 |
